# Finality — бриф на сборку пилотного сайта

> Этот файл — единственный источник правды по проекту. Презентация `finality-concept.pptx` идёт приложением: в ней макеты и картинки. Если текст файла и презентация расходятся, прав файл.
>
> Файл написан так, чтобы его можно было целиком отдать ИИ-агенту (Claude Code, Cursor) как промт, и так, чтобы его прочитал живой разработчик. Разделы «Задача», «Что уже решено» и «Definition of done» — обязательные к прочтению, остальное справочник.

## 1. Задача

Собрать пилотное новостное издание **Finality** — англоязычный сайт о крипте и финтехе для глобального рынка. Это первый из пяти сайтов сети; остальные четыре будут отличаться структурно, а не только цветом, поэтому код с самого начала пишем как переиспользуемую основу, а не как один сайт.

Аудитория: розничные крипто-инвесторы и финтех-профессионалы, читают с телефона в перерывах, хотят за несколько секунд понять, что случилось и почему это важно.

Две задачи интерфейса:
- **Главная**: за 5 секунд показать главное событие дня и увести в ленту.
- **Статья**: дочитывание и переход по внутренним ссылкам.

Разделы: Bitcoin, Ethereum и L2, DeFi, стейблкоины и платежи, регулирование, RWA и токенизация, AI × crypto, финтех, безопасность и взломы, плюс спонсорский раздел Project Spotlight.

## 2. Что уже решено, менять без обсуждения нельзя

Эти решения приняты на этапе концепции и утверждены. Они не предмет творчества исполнителя.

### 2.1 Идея и сигнатурный элемент

Издание называется **Finality** — в блокчейне так называют момент, когда транзакцию уже нельзя откатить.

Сигнатура сайта — **счётчик из шести клеток** рядом с каждым материалом. Каждая клетка = одна пройденная проверка из фиксированного списка:

| № | Проверка |
|---|---|
| 1 | Первоисточник найден и проставлен ссылкой |
| 2 | Ончейн-данные подтверждают утверждение |
| 3 | Независимое второе издание сообщает то же самое |
| 4 | Официальное заявление стороны получено |
| 5 | Цифры сверены редакцией |
| 6 | Подпись выпускающего редактора |

Правила, от которых зависит смысл всей затеи:

- Шесть закрашенных клеток подряд = логотип издания. Логотип и максимальное состояние счётчика — один и тот же объект.
- Счётчик показывается везде, где есть заголовок: лента, главная история, OG-картинка, рассылка, блок «связанные материалы».
- В статье счётчик разворачивается в журнал проверок: у каждой пройденной проверки своё время, у непройденной — статус OPEN.
- **Спонсорский материал не получает счётчик никогда.** Отсутствие счётчика само по себе маркировка.
- Клетки — не декор. Если конкретная проверка не пройдена, клетка пустая, даже когда очень хочется.

### 2.2 Цвет

```css
--ledger:   #F2F4F0;  /* фон страницы: холодная, чуть зеленоватая бумага */
--paper:    #FBFCFA;  /* панели, врезки */
--ink:      #0F1613;  /* текст, закрашенные клетки, тикер */
--graphite: #56615B;  /* второстепенный текст, метаданные */
--rule:     #D3D9D4;  /* линейки и границы */
--pending:  #FFD23F;  /* единственный громкий цвет */
--up:       #0B7A4E;  /* только рост цены */
--down:     #C8322B;  /* только падение цены */
--guest:    #3D5AFE;  /* цвет спонсора, подменяется на каждый Spotlight */
```

Ограничения:

- `--pending` разрешён ровно в четырёх местах: главная история дня, статус «Developing», блок «Риски» в Spotlight, кнопка подписки. Больше нигде.
- `--up` и `--down` — только цены и графики цен. Никогда как акцент интерфейса.
- `--guest` живёт только внутри страницы Spotlight и только в четырёх элементах: плитка логотипа проекта, символ токена, график токеномики, кнопка CTA.
- Контраст: все пары проходят WCAG AA. Проверено: Ink на Ledger 16.6:1, Graphite на Ledger 5.8:1, Up 4.9:1, Down 4.8:1, белый на Guest 5.1:1. При любой правке палитры пересчитать.

Чего в этом проекте не бывает: тёмного фона с неоновым акцентом, фиолетовых градиентов, стеклянных карточек, светящихся сфер. Клиент отверг несколько концепций именно за это.

### 2.3 Шрифты

Все три бесплатные, ставим self-hosted через Fontsource, никаких запросов к Google Fonts.

| Роль | Шрифт | Где применяется |
|---|---|---|
| Display | **Redaction** 700 | Все редакционные заголовки, названия разделов |
| Status | **Redaction 70** 700 | Единственное слово «DEVELOPING». Больше нигде |
| Body | **Atkinson Hyperlegible Next** 400/700 | Весь основной текст, интерфейс |
| Data | **Martian Mono** 400/600 | Цены, время, хэши, метки, счётчики |

Почему Atkinson: он разработан для слабовидящих, у него различимы 0/O и 1/l/I. В новостях, где смысл несут суммы и адреса, это функциональное требование, а не вкус.

**Заголовки Spotlight набираются гротеском (Atkinson), а не Redaction.** Redaction = редакция. Это второй уровень защиты от путаницы со спонсорским контентом.

Типографическая шкала (десктоп): 84 / 60 / 40 / 28 / 21 / 18 / 11. Мобильная: 40 / 28 / 21 / 18.5 / 16.5 / 11.

### 2.4 Композиция

- Сетка 12 колонок, поля 24 px, максимальная ширина 1440 px.
- Главная: лента `1fr` + правый рельс `380px`. Главная история: `1fr` + журнал проверок `360px`.
- **Лента — это строки реестра, а не сетка карточек**: время, счётчик, заголовок, раздел. Без теней, без скруглений, без превью-картинок в ленте.
- Скругления в проекте отсутствуют как класс. Радиус 0 везде, кроме аватаров авторов.
- Единственная пунктирная рамка на сайте — вокруг спонсорского блока.

## 3. Стек и ограничения

- **Astro** со static output, острова только там, где нужна интерактивность (тикер, ⌘K, журнал проверок, мобильное меню). Альтернатива — Next.js с ISR, если клиент настаивает; тогда ревалидация главной 60 секунд.
- Контент — markdown/MDX в репозитории на старте, с готовностью переехать в headless CMS. Структура фронтматтера описана в разделе 6.
- Никаких UI-китов и готовых тем. CSS пишем руками, токены из раздела 2.2 в `:root`.
- JS в ленте минимальный. Страница должна быть полностью читаема и без него.
- Изображения: AVIF/WebP, `srcset`, обязательные `width`/`height`.

## 4. Шаблоны страниц

### 4.1 Главная

Сверху вниз: тикерная лента → шапка с логотипом, навигацией по разделам и поиском → главная история дня → лента последних материалов с правым рельсом → подписка.

Главная история занимает первый экран, фон `--pending`. Внутри: раздел, статус, время обновления, H1, лид, автор с фото. Справа (на десктопе) или снизу (на мобильном) — журнал проверок.

Правый рельс: рыночная панель (с явной пометкой источника данных), блок Project Spotlight в пунктирной рамке, хабы разделов со счётчиком материалов за день, форма подписки.

Мобильная главная: тикер → шапка → свайп-табы разделов → главная история с заголовком 40 px → лента строками. Главный заголовок должен помещаться на первый экран телефона 360 px целиком вместе с лидом и счётчиком.

### 4.2 Новость или статья

Хлебные крошки → раздел и статус → H1 → лид → автор с фото и био → даты публикации и обновления в `<time datetime>` → блок «Key takeaways» из трёх пунктов до текста → оглавление для лонгридов (липкое на десктопе, выпадающее на мобильном) → текст с врезками данных каждые 3–4 абзаца → три связанных материала со счётчиками → карточка автора.

Длина строки 64 знака, кегль 18 px, интерлиньяж 1.6.

Жёлтая плашка у заголовка ведёт в журнал проверок. Журнал раскрывается на месте, страница при этом не прыгает.

### 4.3 Project Spotlight

Спонсорская статья о проекте. Проект получает свой акцентный цвет, но остаётся гостем в чужой дизайн-системе.

Порядок блоков:

1. Чёрная плашка «Partner content · Paid for by [Project]» — над всем, включая hero. Видна до скролла.
2. Hero: плитка логотипа проекта в цвете `--guest`, заголовок гротеском, лид.
3. Панель ключевых фактов: сеть, токен, дата запуска, аудиты, инвесторы, TVL или объём.
4. «Что это» простыми словами.
5. «Как это работает» со схемой.
6. Токеномика с графиком распределения.
7. Роадмап таймлайном. **Здесь нумерация уместна**, потому что это настоящая последовательность. В остальных местах сайта декоративных номеров 01/02/03 нет.
8. Команда и бэкеры.
9. **«Риски и открытые вопросы»** — обязательный блок, фон `--pending`, заголовок в Redaction, подпись «Added by Finality editors». Пишет редакция, не клиент. Это то, что делает раздел продаваемым и не убивает E-E-A-T.
10. FAQ.
11. CTA на официальный сайт: `rel="sponsored noopener"`, подпись объясняет, что откроется.

Счётчика проверок на этой странице нет. Рамка вокруг контента пунктирная.

### 4.4 Хаб раздела или тега

Вводный текст 150–300 слов (он и есть SEO-смысл страницы) → закреплённые материалы → лента → пагинация `?page=2` с self-canonical.

### 4.5 Страница автора

Фото, экспертиза, соцсети через `sameAs`, список всех материалов. Нужна не для читателя, а для доверия и разметки Person.

## 5. Моушен

Спека целиком. У каждой анимации указано назначение. **Если у анимации нет назначения — её нет.**

| Элемент | Триггер | Длительность | Easing | Назначение |
|---|---|---|---|---|
| Тикерная лента | Всегда | ~40 px/с | `linear` | Показывает, что рынок живой. Пауза при hover и при `document.hidden` |
| Вспышка цены | Новый тик | 160 мс вкл / 180 мс выкл | `ease` | Какая цена изменилась. Только `background-color` через transition, не keyframes |
| Заполнение клеток в hero | Первая загрузка за сессию | 220 мс, stagger 60 мс | `cubic-bezier(.23,1,.32,1)` | Единственная оркестрованная сцена. Объясняет, что клетки копятся |
| Новая проверка в живой истории | Push с сервера | 200 мс | `cubic-bezier(.23,1,.32,1)` | Индикация состояния: одна клетка заполнилась |
| Поиск и ⌘K | Клавиатура, клик | 0 мс | — | Открывается десятки раз в день. Анимация только мешает |
| Hover строки ленты | `hover: hover` и `pointer: fine` | 150 мс | `ease` | Обратная связь на наведение |
| Нажатие кнопки | `:active` | 120 мс | `cubic-bezier(.23,1,.32,1)` | `scale(0.97)`: интерфейс услышал |
| Мобильное меню | Тап | 240 вход / 180 выход | `cubic-bezier(.32,.72,0,1)` | Пространственная связь: выезжает от края, туда же уходит |
| Журнал проверок | Клик | 200 вход / 150 выход | `cubic-bezier(.23,1,.32,1)` | `grid-template-rows: 0fr → 1fr`, без скачка текста |
| Тост «Subscribed» | Отправка формы | 200 вход / 150 выход | `cubic-bezier(.23,1,.32,1)` | Подтверждает действие. Слово совпадает с кнопкой Subscribe |

Правила:

- Выход всегда быстрее входа.
- Никакого `transition: all` и никакого `ease-in` на UI.
- Все hover-эффекты внутри `@media (hover: hover) and (pointer: fine)`.
- `prefers-reduced-motion: reduce` — лента становится статичным списком, stagger и сдвиги убираются, клетки проявляются только прозрачностью, вспышки цвета остаются.
- Не анимируем: переходы страниц, подъём карточек при наведении, scroll-reveal, параллакс.

## 6. SEO

### 6.1 URL и разметка

| Шаблон | URL | JSON-LD |
|---|---|---|
| Главная | `/` | `Organization` с логотипом, `WebSite` + `SearchAction` |
| Новость | `/news/{slug}` | `NewsArticle`, `BreadcrumbList`, `Person` |
| Разбор в разделе | `/defi/{slug}`, `/policy/{slug}` … | `NewsArticle` или `Article` для эксплейнеров |
| Spotlight | `/spotlight/{slug}` | `Article`, `FAQPage`, `BreadcrumbList` |
| Хаб раздела и тега | `/defi/`, `/tag/{tag}/` | `CollectionPage`, `ItemList`, `BreadcrumbList` |
| Автор | `/author/{name}` | `ProfilePage` + `Person` с `sameAs` |

### 6.2 Обязательная гигиена

- Семантический HTML5: `article`, `header`, `nav`, `time datetime`. Один H1 на страницу, иерархия заголовков без пропусков.
- `datePublished` и `dateModified` на каждом материале. При существенной правке — видимая пометка об исправлении.
- Open Graph и Twitter-карточки. Шаблон OG-изображения: жёлтый фон, счётчик, заголовок Redaction, логотип (макет в презентации).
- `sitemap.xml`, отдельный news-sitemap (материалы за последние 48 часов), RSS по разделам. `hreflang` закладываем в архитектуру, включаем только когда появятся языковые версии.
- Спонсорский контент: видимая плашка + `rel="sponsored"` на всех исходящих ссылках. Это требование спам-политик Google, а не наша перестраховка.

### 6.3 Core Web Vitals

Цели: LCP < 2.5 с, CLS < 0.1, INP < 200 мс.

- LCP — это текст заголовка, а не картинка. В hero картинки нет by design.
- Preload одного файла: Redaction 700, latin subset. `font-display: swap`, для запасного шрифта прописать `size-adjust`, чтобы подмена не двигала текст.
- Тикер фиксированной высоты, резерв места под рекламу и изображения — иначе CLS.
- Замер на реальном мобильном соединении, не на десктопном Lighthouse.

### 6.4 Перелинковка

Схема: хаб раздела → статья → связанные материалы → автор.

- Каждая статья: ссылка на хаб раздела через крошки, 2–4 ссылки в тексте на объясняющие материалы, 3 связанных внизу, ссылка на автора.
- Связанные подбираются по разделу или по сущности (протокол, актив), не случайно.
- В Spotlight ведут только хаб `/spotlight/` и помеченный блок на главной. Редакционные «связанные материалы» на спонсорские страницы не ссылаются.

## 7. Контент

Никакого lorem ipsum ни на одном этапе, включая черновую вёрстку. Для запуска нужно 10–12 реальных новостей за последние 7 дней по разным разделам: потоки в ETF, регулирование, стейблкоины, RWA, DeFi, взломы, финтех-платежи, AI × crypto.

Заголовки и лиды пишутся своими словами, тексты источников не копируются. Ссылка на первоисточник — обязательное поле, а не опция: без неё не закрывается проверка №1.

Цены и графики в демо-режиме помечаются как демо-данные прямо в интерфейсе. Когда подключится реальный источник котировок, пометка убирается вместе с моком.

Минимальный фронтматтер материала:

```yaml
title: ""
dek: ""            # лид
slug: ""
section: ""        # bitcoin | ethereum | defi | stablecoins | policy | rwa | ai | fintech | security
status: ""         # developing | final
publishedAt: ""    # ISO 8601
updatedAt: ""
author: ""         # slug автора
checks:            # журнал проверок, только пройденные
  - id: 1
    at: ""
sources:
  - url: ""
    title: ""
related: []        # slug'и, 3 штуки
sponsored: false   # true только для Spotlight
```

Тексты интерфейса: активный залог, кнопка говорит, что произойдёт. «Get the 7:00 brief», «Subscribe», «Go to project.xyz». Название действия не меняется по ходу флоу: кнопка Subscribe даёт тост Subscribed.

## 8. Definition of done

Сайт считается сданным, когда выполнено всё:

**Функциональность**
- [ ] Все пять шаблонов собраны: главная, статья, Spotlight, хаб раздела, страница автора.
- [ ] На сайте 10–12 реальных материалов, у каждого проставлены источники и журнал проверок.
- [ ] Тикер работает, встаёт на паузу при hover и в скрытой вкладке.
- [ ] ⌘K открывает поиск мгновенно, без анимации.

**Качество исполнения**
- [ ] Адаптив до 360 px без горизонтального скролла.
- [ ] Видимый фокус клавиатуры на всех интерактивных элементах, порядок табуляции логичный.
- [ ] `prefers-reduced-motion` реализован по разделу 5.
- [ ] Контраст не ниже WCAG AA на всех парах.
- [ ] Сайт читаем с выключенным JS.

**SEO**
- [ ] JSON-LD по разделу 6.1 валидируется в Rich Results Test без ошибок.
- [ ] Один H1 на страницу, иерархия без пропусков.
- [ ] sitemap, news-sitemap, RSS отдаются и валидны.
- [ ] LCP < 2.5 с, CLS < 0.1, INP < 200 мс на мобильном.

**Проверка по фирменному стилю** (прогнать перед сдачей)
- [ ] Если закрыть логотип, издание узнаётся? Если нет — сигнатура реализована слабо.
- [ ] Нет ли на сайте одинаковых карточек с одним радиусом и одной тенью?
- [ ] Каждый структурный элемент (нумерация, лейблы, разделители) несёт информацию, а не украшает?
- [ ] Главная история читается за 5 секунд на экране 360 px?
- [ ] Спонсорский материал нельзя спутать с редакционным: плашка, нет счётчика, пунктир, другой шрифт заголовка?

## 9. Что нужно получить от клиента до старта

1. Подтверждение названия **Finality** и домена.
2. Логотип и цвет первого спонсора для Spotlight, плюс данные проекта: название, сайт, описание на 2–5 предложений, сеть, токен, аудиты, инвесторы.
3. Источник рыночных данных: свой API-ключ или наш выбор провайдера (влияет на бюджет).
4. Фото, био и соцсети авторов — без них не закрывается разметка `Person` и половина смысла E-E-A-T.
5. Решение по CMS: остаёмся на markdown в репозитории или сразу подключаем headless.

## 11. Страница «Проекты» (добавлено после запуска пилота)

Разобрали DappRadar API: требует регистрации, практический продакшн-тариф — Premium for Developers

### Строки должны открываться, а не просто быть подписями

Первая версия страницы была статичными надписями без возможности что-либо узнать о проекте.
Исправлено:

- **Строки блокчейнов** — обычные ссылки на страницу сети в DeFiLlama (`target="_blank"`).
  У бесплатного API блокчейнов нет описания или сайта — раскрывать там нечего, поэтому это ссылка,
  а не аккордеон.
- **Строки протоколов и «Актуальных проектов»** — `<details>`-аккордеон, та же техника
  `grid-template-rows: 0fr → 1fr`, что и в `VerificationLog` (см. раздел 5): без единой строки JS,
  выход быстрее входа. Внутри: описание проекта, категория, изменение TVL за 7 дней, число
  аудитов, дата появления в реестре DeFiLlama, **разбивка TVL по сетям** в виде полосок (поле
  `chainTvls`, очищенное от служебных ключей вроде `-borrowed`/`-staking`, иначе кредитные
  протоколы задваивают TVL), **лента заметных событий** там, где DeFiLlama её ведёт (поле

  сайт проекта, X (Twitter), отчёт аудита и полную карточку на DeFiLlama. Всё это — из того же
  ответа API, что и сама строка, второго запроса не требуется.
- **Редизайн по замечаниям клиента (второй проход).** Пять реальных багов и три содержательных
  пробела, найденных при живом просмотре страницы:

  `--paper`, `object-fit: contain`. Радиус 0, как и требует раздел 2.4 (скругления — только у
  аватаров авторов). Разница источников осталась, но теперь она внутри одной системы, а не
  вместо неё.
- **Баг с колонками у строк блокчейнов.** Стрелка «↗» уезжала на отдельную строку под номером —
  причина в специфичности CSS: базовое правило было написано как `a.row` (элемент + класс), а
  переопределение для сетей — как `.chain-row` (только класс). У `a.row` специфичность выше, и
  переопределение молча проигрывало независимо от порядка в файле. Починено переводом обоих
  правил на одинаковый уровень специфичности (`a.row` / `details.row > summary` как база,
  `a.row.chain-row` / `details.proto-row > summary` как переопределения) — теперь побеждает то
  правило, которое должно.

### Почему строки не обновляются сами

У первой версии было автообновление таблиц раз в 90 секунд поверх всей разметки. С аккордеонами
это ломает UX: замена innerHTML строки схлопывает открытую пользователем карточку прямо во время
чтения. Решение — убрать периодическое обновление таблиц целиком. Цифры актуальны на момент
последней сборки/открытия страницы, не в реальном времени — как и Ticker/MarketsPanel по сути,
только без плашки, намекающей на живое обновление. Это же приближает страницу к принципу раздела 3
(«не берём» дашборд как основной интерфейс для розницы) — статичная таблица, которую читают один
раз за визит, а не то, за чем следят как за биржевым терминалом.

### Платное размещение своего проекта

**Не встраивается внутрь настоящего рейтинга** — это разрушило бы единственную вещь, ради которой
существует Finality: доверие к цифрам. Вместо этого — отдельный блок рядом с таблицами, тот же
визуальный язык, что уже есть у Project Spotlight на главной (`SpotlightTeaser`: пунктирная рамка,
плашка «Партнёрский материал», ведёт на `/spotlight/{slug}/`). Пока используется существующий
шаблон-заглушка `project-template`; станет реальным, когда появится настоящий спонсор
(см. раздел 9, пункт 2).

### Статьи в разделе

Позже клиент добавит материалы, которые ссылаются на данные со страницы «Проекты» (например,
разбор роста TVL конкретного протокола). Отдельного шаблона под это не требуется — обычная статья
из `src/content/news/`, `related` может указывать на неё со страницы `/projects/` при необходимости

## 12. Тёмная тема (добавлено по запросу клиента)

Переключатель в шапке (`ThemeToggle.astro`, солнце/луна рядом с кнопкой поиска), не привязан
к системной теме — читатель выбирает сам, выбор запоминается в `localStorage`. При первом визите
без сохранённого выбора используется `prefers-color-scheme` как разумный дефолт.

**Механизм.** Всё завязано на уже существующие 9 цветовых токенов из `tokens.css` — тёмная тема
не добавляет новых цветов, а переопределяет те же роли (`--ledger`, `--paper`, `--ink`,
`--graphite`, `--rule`, `--up`, `--down`, `--guest`) через `:root[data-theme='dark']`. Компоненты
не знают о теме вообще, они просто читают переменные — переключение темы не потребовало трогать
разметку ни одного компонента, кроме самого переключателя.

Один нюанс: несколько блоков (тикер, CTA-плашка на странице Spotlight) сделаны как
`background: var(--ink); color: var(--ledger)` — специально «всегда тёмная плашка» на фоне более
светлой страницы. В тёмной теме `--ink`/`--ledger` меняются ролями, поэтому такая плашка не остаётся
тёмной — она честно инвертируется в светлую на фоне уже тёмной страницы, что сохраняет тот же
контраст, просто зеркально. Единственное, что при этом ломается — два-три цвета внутри тикера
(`--up`/`--down`/подпись), которые были захардкожены под конкретно тёмный фон; для них добавлены
точечные `:root[data-theme='dark']`-переопределения, возвращающие исходные (светлотемные) значения,
потому что для инвертированной (посветлевшей) плашки нужен ровно противоположный набор оттенков.

**Анимация переключения.** При клике на `<html>` на ~300ms вешается класс `.theme-transitioning`,
который через `*` навешивает `transition` на `background-color`/`color`/`border-color` — вся
страница мягко перетекает между палитрами, а не переключается одним кадром. Класс снимается после
анимации, чтобы не мешать точечным transition’ам компонентов (наведение, аккордеоны и т.д. — они
специфичнее и всегда выигрывают). Уважает `prefers-reduced-motion`.

**Защита от вспышки при загрузке.** Инлайн-скрипт в `<head>` (до всех стилей) читает
`localStorage`/`prefers-color-scheme` и сразу проставляет `data-theme` на `<html>` — иначе страница
на мгновение показала бы светлую тему и тут же переключилась на тёмную для читателя, который её уже
выбрал.

**Заодно исправлено:** плейсхолдер `[Project]` из `project-template.md` тоже утекал на главную
страницу (`index.astro`) и даже собирался в отдельную публичную страницу `/spotlight/project-template/`
(через `getStaticPaths`, без фильтра) — оба места получили ту же проверку на квадратные скобки,
что уже стояла на `/projects/`.

**Найденный после запуска баг: белый текст на жёлтом.** Три блока — hero-баннер на главной,
виджет подписки, блок «Риски» на странице Spotlight — стоят на постоянной жёлтой заливке
`--pending`, которая не меняется между темами. Текст внутри них не был расписан явно и просто
наследовал `var(--ink)` от `<body>` — в светлой теме это тёмный текст на жёлтом (нормально), но
в тёмной `--ink` становится почти белым, и жёлтый фон остаётся жёлтым: белый текст на жёлтом,
провал по контрасту. Исправлено через новый токен `--on-accent: #0f1613` в `tokens.css` —
фиксированный тёмный цвет, который **не переопределяется** под `[data-theme='dark']` (в этом весь
смысл: он не должен меняться вместе с темой). Применён везде, где текст сидит прямо на
`--pending`: явные `color: var(--on-accent)` на заголовках/подписях/врезках, и локальное
переопределение `--ink: var(--on-accent)` на уровне контейнера там, где внутри есть переиспользуемый
компонент без пропа для цвета (`VerificationMeter` в hero) — кастомные свойства наследуются по
DOM-дереву независимо от того, в каком файле объявлены, так что это не потребовало трогать сам
компонент.

## 13. Поиск и фильтр по категории на «Проектах»

`FilterBar.astro` — поиск по названию (дебаунс 150ms) и чипы категорий над таблицами «Топ
протоколов» и «Актуальные проекты». Без клиентского фреймворка и стора: строки уже отрендерены
на билде, фильтр просто переключает нативный атрибут `hidden` по двум `data-*` на каждой строке
(`data-name`, `data-category`). Категории — не придуманная таксономия, а реальные значения поля
`category` из ответа DeFiLlama, посчитанные отдельно для каждой таблицы, чтобы не показывать чип,
под которым нет ни одной строки.

Таблица блокчейнов фильтром не накрыта — у DeFiLlama `/v2/chains` нет поля категории, и с 10
строками поиск не нужен.

**Пойманный при реализации баг:** первая версия искала целевую таблицу через
`bar.nextElementSibling`, но Astro выводит `<script>`/`<style>` компонента как соседние узлы сразу
после его разметки — в реальном DOM следующим элементом после `.filter-bar` оказывался `<script>`,
а не `.table`, и фильтр молча ничего не находил (0 строк). Исправлено обходом соседей вперёд до
первого элемента с классом `.table`.

## 14. Страница «О редакции»

Найден реальный пробел: футер на каждой странице сайта текстом обещал «Общая информация об
издателе — на странице About», а самой страницы никогда не существовало (404). Это и битое

источников доверия, которые проверяют вручную.

`src/pages/about/index.astro` закрывает это тремя блоками:

- **Редакция** — карточки трёх авторов (переиспользует `src/content/authors/`), с прямыми

  темы у авторов, но не реальные фото/соцсети, и что у Spotlight — только шаблон, а не
  проданное размещение. Это тот же принцип честности, что уже применялся к плейсхолдерам
  Spotlight и инициалам авторов вместо фото — просто теперь собранный в одном месте.

Текст в футере превращён в настоящую ссылку на `/about/`. При написании раздела «Если мы
ошиблись» чуть не повторилась та же ошибка, что и с самим футером: черновик ссылался на
«контакты издания», которых на сайте физически не существует (ни email, ни формы). Исправлено
на честное признание, что публичного канала для правок на этапе пилота пока нет — не стоило
чинить один битый промис, создавая рядом второй.

## 15. Баг на странице статьи: разъехавшийся сайдбар и тройной повтор слов

Клиент прислал скриншот с разметкой: между датами публикации и блоком верификации — гигантский
пустой отступ, а слово «Регулирование»/«РАЗВИВАЕТСЯ» повторяется три раза на одном экране.

**Причина отступа — реальный баг CSS Grid, не косметика.** `.dates` был растянут на 2 строки
грида (`grid-row: 2 / span 2`), а вторая из этих строк — та же строка, где `.prose` (весь текст
статьи) сидит в первой колонке. Высота строки определяется самым высоким элементом в ней — то
есть всей статьёй, тысячи пикселей. `.dates` растягивался на всю эту высоту, но его контент
(две короткие строки) выравнивался по верху (`align-content:start`) — а следующий элемент
сайдбара (`VerificationLog`, ранее — `.log-slot` в отдельной строке 3) начинался только там, где
заканчивалась строка 2, то есть далеко внизу. Итог: даты и чек-лист визуально разъезжались на
сотни пикселей, хотя в разметке шли друг за другом.

**Исправление:** даты, `VerificationLog`, `RelatedList` и `AuthorCard` объединены в один
`<aside class="rail">` — единый grid-элемент, растянутый на те же строки (`2 / span 2`), что и
`.art-header` + `.prose` в первой колонке, но с собственным `display:grid; gap:32px;
align-content:start`. Теперь высота строк грида управляется основной колонкой, а сайдбар просто
стекуется по своей собственной высоте внутри выделенного места — та же техника, что уже
использовалась в `.side` для related+author, просто применённая ко всему сайдбару целиком.

**Тройной повтор слов.** Хлебные крошки называли раздел («Регулирование»), сразу под ними
эйбрау-тег в `.tags` повторял то же слово капсом плюс статус («РАЗВИВАЕТСЯ»), а чуть ниже — уже
внутри `VerificationLog` — статус повторялся третий раз. Название раздела в `.tags` убрано целиком
(крошки уже сообщают его секундой раньше) — из тега остался только статус, который несёт
самостоятельный смысл прямо над заголовком, до того как читатель доберётся до чек-листа снизу.

**Побочный баг, найденный при проверке.** После объединения сайдбара в `.rail` шириной 280px
контент несколько раз пробивал эту границу и вылезал за правый край экрана: строка статуса внутри
`VerificationLog`, роль автора в `AuthorCard`. Причина одна и та же в обоих случаях — flex/grid-
элементы по умолчанию не сжимаются у́же своего `min-content` (`min-width: auto`), а длинный
неразрывный текст («РАЗВИВАЕТСЯ», «Редактор раздела регулирования») этот `min-content` завышал.
Добавлено `min-width: 0` на `.rail`, на `summary` внутри `VerificationLog` (плюс `flex-wrap: wrap`,
чтобы статус мог уйти на свою строку) и на `.text` внутри `AuthorCard`.

## 16. Видео-виджет

По запросу клиента добавлен минимальный видео-модуль — реальные YouTube-ролики с именованных
новостных каналов (CNBC Crypto World), не выдуманный контент и не интеграция с платным видео-API,
которого для бесплатного крипто-видео просто не существует. Тот же принцип «честный источник или
никак», что и у остальной редакции.

**Модель данных.** Новая коллекция `src/content/videos/` (схема в `content.config.ts`): `title`,
`youtubeId`, `channel`, `section`, `addedAt`, `note` (одна строка контекста от редакции — как это
видео связано с уже написанным материалом Finality). Четыре ролика на старте, у каждого реальный
`youtubeId`, проверенный вручную.

**Производительность — facade-паттерн, не голый `<iframe>`.** `VideoWidget.astro` по умолчанию
рендерит только статичную картинку превью (`i.ytimg.com/vi/{id}/hqdefault.jpg`) и кнопку play —
ни один скрипт и трекер YouTube не грузится, пока читатель сам не кликнёт. По клику в DOM
создаётся настоящий `<iframe>` на `youtube-nocookie.com` (не `youtube.com` — куки трекинга не
ставятся, пока видео физически не запущено). Тот же принцип, что и у ленивой загрузки картинок
статей: не платить цену тяжёлого виджета тем, кто его не смотрит.

**Размещение.** На главной — рейл сайдбара, до трёх последних роликов. На страницах разделов —
не отдельный сайдбар (у хабов его нет и делать ради одного виджета не стали), а один релевантный
ролик компактным блоком между вступлением и лентой статей, если для раздела он есть. Список — не
подборка «всё про Х», а осознанно узкий: один ролик на раздел, потому что это текстовое издание
с журналом проверок, а не видео-хаб, и превращать сайдбар в вечную ленту YouTube не стоит.

## 17. Спарклайны на «Проектах» + ещё 2 статьи

Довели до конца обещание из более раннего ревью страницы «Проекты»: у каждой раскрытой строки
протокола/лидера роста теперь есть настоящий график TVL за 30 дней — тонкая линия без осей, без
заливки, без легенды, цвет по тренду теми же токенами `--up`/`--down`, что и везде на сайте, без
третьего акцента специально под график.

**Данные настоящие.** `/protocol/{slug}` у DeFiLlama отдаёт всю историю TVL протокола (тысячи
точек) — `fetchTvlHistory()` в `defillama-client.ts` берёт последние 30 и кэширует по slug на
процесс сборки, так что один и тот же протокол, встречающийся и в топ-15 по TVL, и в топ-10 по
росту, не тянется дважды. `sparklinePath()` — чистая функция, превращающая массив чисел в набор
точек `<polyline>` с нормализацией под min/max; ноль зависимостей, ноль JS на клиенте, SVG
рендерится на билде как обычная разметка.

**Цена — время сборки.** Раньше страница делала 2 запроса к DeFiLlama (список сетей + список
протоколов), теперь плюс ~20 (по числу уникальных протоколов с известным `slug`) — сборка всей
страницы выросла примерно с 10 до ~25 секунд. Для статического сайта, который не пересобирается
на каждый чих, это разумная цена за настоящие данные вместо фейкового графика.

Заодно — ещё две статьи по той же исследовательской методике, что и раньше: реальный источник,
честная оговорка там, где цифры у трекеров расходятся (доля L2-транзакций у growthepie называется
то 93%, то 94%, то «в 13 раз», то «в 15 раз» — сохранили диапазон, а не выдуманную точность), и
проверенные `related:`-связи в обе стороны.

## 18. Три бага, найденные при живом просмотре: видео, даты, бесконечная лента

**Видео сжималось при запуске.** При клике по превью новый `<iframe>` создавался в JS и получал
класс `.yt-iframe`, но Astro компилирует скоуп-стили в вид `.yt-iframe[data-astro-cid-xxx]` —
атрибут-скоуп проставляется только элементам, присутствующим в серверной разметке при сборке.
Динамически созданный элемент его никогда не получает, поэтому весь CSS класса (ширина,
`aspect-ratio`, рамка) молча не применялся, и iframe откатывался к дефолтным 300×150px браузера —
визуально это читалось как «квадратик уменьшается на пару сантиметров». Исправлено: ширина,
`aspect-ratio` и рамка на новом iframe задаются инлайн-стилем (`iframe.style.cssText = ...`)
прямо в скрипте, а не через класс — инлайн-стили применяются независимо от скоупинга.

**Стена одинаковых «00:00».** У всех статей `publishedAt` стоит на условную полночь (это
редакционная метка, не реальное время суток), а `ArticleRow` показывал только `HH:MM` из неё —
в любой ленте длиннее пары статей на экране был лес повторяющихся «00:00», что читалось как
незаполненная заглушка. Заменено на дату (`ДД.ММ`) — она и правдива, и осмысленна при просмотре
ленты за недели, в отличие от времени, которое никогда не было настоящим временем публикации.

**Главная страница выгружала весь архив одним полотном.** С ростом числа статей до 40 лента на
главной (`{feed.map(...)}` без ограничения) стала бесконечной простынёй строк без деления на
страницы — не «свежие материалы», а весь архив сайта на одной странице. Ограничено до 12 последних
(`FEED_SIZE`); остальное остаётся доступным через хабы разделов (уже есть ссылки в сайдбаре) и
страницы авторов — отдельная пагинация на главной не нужна, это не архивная страница.

## 19. Превью-картинки в списках статей

Список статей (`ArticleRow.astro` — используется на главной, в хабах разделов, на страницах
пагинации и на страницах авторов) был чисто текстовым: время/дата, чек-меттер, заголовок, дек,
раздел — без единой картинки. На фоне того, что сама статья уже открывается с полноценным фото,
список выглядел заметно суше своей же собственной страницы.

**Решение — переиспользовать то, что уже есть, не изобретать новый источник изображений.**
`ArticleRow` теперь принимает `imageQuery`/`slug` и сам решает: если у статьи есть `imageQuery` —
показывает превью того же фото с Pexels, что видно на странице статьи; если нет (или ключ Pexels
не настроен, или поиск ничего не вернул) — тот же самый хэш-сгенерированный `ArticleSeal`, что
служит фолбэком на странице статьи, просто в масштабе 4×4 вместо 18×5. Ни одна строка списка не
остаётся совсем без визуала, и ни для одной не выдумывается новая картинка.

**Не вторая порция запросов к Pexels.** `fetchThemedPhoto()` кэширует по строке запроса на весь
процесс сборки; та же самая статья на своей собственной странице уже дёргает Pexels по тому же
`imageQuery` — список просто читает готовый результат из кэша. Единственное отличие — размер:
списки берут `photo.src.medium` (~350px), а не `large` (940px), который использует полноразмерное
фото на странице статьи, — превью в строке высотой 64px не должно тянуть тот же вес, что герой-фото
статьи.

**Клиентский фидбэк после первой версии: превью «выглядят не очень».** Дюжина фотографий от
разных авторов Pexels, сжатых до 64–76px, конфликтовала по цвету и качеству кропа — рядом с
засечным заголовком это читалось шумно и дёшево. Решение то же, что нашли газеты и журналы задолго
до CSS: единая дуотон-обработка всех фото в списке вместо демонстрации их «как есть». Каждое фото
в `ArticleRow` теперь проходит `filter: grayscale(75%) sepia(8%) contrast(1.05)` — приглушает
разномастные цвета и слегка тонирует под тёплую бумажную палитру сайта, вместо того чтобы с ней
конфликтовать. Цвет возвращается при наведении (`grayscale(0%)`, лёгкий `scale(1.08)`) — это и
награда за интерес к конкретной строке, и намёк, что открыв статью, читатель увидит то же фото уже
в полном цвете. Заодно увеличил рамку с 64 до 76px — на таком крошечном размере кадр было тяжело
считать визуально вообще, независимо от цвета.

## 20. Поиск и фильтр по разделу на главной

Переиспользован `FilterBar.astro` — тот же компонент, что уже фильтрует таблицы на `/projects` —
теперь ещё и над лентой «Последние материалы» на главной: поиск по заголовку с дебаунсом и чипы
по разделам (посчитаны от реально показанных 12 статей, а не от всех девяти разделов сайта — чип
без единой подходящей строки никому не нужен).

**Обобщение, а не копия.** Раньше компонент был жёстко привязан к классу `.table` при поиске
своего целевого контейнера (`bar.nextElementSibling`, пока не найдёт `.table`). Добавлен проп
`targetClass` (по умолчанию `'table'`, на главной — `'feed'`), чтобы один и тот же компонент
работал и с таблицами `/projects`, и с лентой статей, без дублирования кода ради одного другого
имени класса. Разметку на главной пришлось чуть перестроить: раньше заголовок «Последние
материалы» жил внутри `<section class="feed">` вместе со строками — теперь он снаружи, а фильтр-бар
встаёт между заголовком и `<section class="feed">`, которая используется как есть в роли
`targetClass`.

**Баг, пойманный при проверке: фильтр молча ничего не скрывал на главной.** `ArticleRow.astro`
задаёт `.row { display: grid; }` — авторское правило с той же специфичностью (0,1,0 после
компиляции класс-селектора), что и `[hidden] { display: none }` у браузера. При равной
специфичности побеждает автор, а не user-agent — то самое правило, которое в этом проекте уже
один раз ломало поисковый оверлей и трогало сайдбар на «Проектах». JS корректно проставлял
атрибут `hidden` на скрытые строки, но визуально они не пропадали — чипы и поиск выглядели
полностью нерабочими на скриншоте, хотя `row.hidden` в DOM был `true`. Поймано не по скриншоту,
а прямой проверкой `row.hidden` через Playwright, что и разошлось с картинкой на экране — сразу
подсказка, что дело в CSS, а не в логике фильтра. Исправлено явным `.row[hidden] { display: none; }`
— та же техника, что уже применялась для этого класса багов. На `/projects` та же проблема не
проявлялась, потому что там `display:grid` стоит на `<summary>` внутри `<details>`, а `hidden`
ставится на сам `<details>`, у которого никакого конкурирующего авторского правила на `display`
нет.

## 21. Переключатель «Таблица / Карточки» на «Проектах»

Последний пункт из клиентского Web3-брифа про /projects, который ещё не был закрыт. Реализовано
без единой строки JS — два скрытых `<input type="radio">` плюс `label`, стилизованные как
сегмент-контрол, и современный CSS-селектор `:has()` вместо скрипта:

```css
.view-controls:has(#view-cards:checked) ~ .layout .protocol-table { display: none; }
.view-controls:has(#view-cards:checked) ~ .layout .protocol-cards { display: grid; }
```

Тот же принцип, что уже используют аккордеоны на этой странице ([open]-атрибут) и мобильное меню
— нативный элемент управления состоянием плюс CSS, без обработчиков событий.

**Область действия.** Переключатель затрагивает только «Топ протоколов» и «Актуальные проекты» —
именно там есть что показать в карточке (спарклайн, описание, дельты). Таблица блокчейнов
(10 простых ссылок без второй метрики) в карточном виде ничего бы не выиграла и остаётся списком
всегда.

**Карточка переиспользует уже посчитанные данные**, а не делает вторую версию контента: та же
history-функция `sparkFor(p.slug)` из аккордеона, тот же `fmtTvl`/`fmtChange`, то же реальное
`p.description` от DeFiLlama (обрезано до двух строк через `-webkit-line-clamp`). Карточка —
обычная ссылка на DeFiLlama, а не мини-аккордеон: раскрытие с разбивкой по сетям и лентой событий
осталось эксклюзивной фичей табличного вида, чтобы не дублировать сложную интерактивность дважды.

**Баг, пойманный при первой проверке: скрытие фильтра не сработало.** Правило
`~ .layout .filter-bar { display: none; }` не матчило реальный DOM. Причина — `.filter-bar`
рендерится дочерним компонентом `FilterBar.astro` и несёт **его** scope-атрибут Astro, а не
атрибут страницы; селектор, написанный в `projects/index.astro`, компилируется с добавлением
атрибута *этой* страницы к каждому сегменту, включая `.filter-bar`, и в итоге не совпадает ни с
одним реальным элементом. Тот же класс проблемы, что уже ловился на `bar.nextElementSibling` в
JS этого же компонента — только на этот раз в CSS. Исправлено через `:global(.filter-bar)`,
которое выводит этот сегмент селектора из скоупинга страницы.

## 22. Английская версия (инфраструктура + интерфейс, статьи пока RU)

По решению клиента: английский — для международной/EU-аудитории, русский остаётся основным для
СНГ. Осознанно ограниченный первый шаг — переведена **вся оболочка сайта** (навигация, поиск,
подписка, виджет рынков, футер, breadcrumbs, лейблы разделов и статусов), но **тексты самих
статей остаются русскими** — перевод 52 реальных материалов вручную это отдельная по объёму
задача, и делать её «между делом» значило бы либо тянуть месяцами, либо схалтурить с качеством
перевода. На каждой английской странице — честный баннер об этом (`t.notTranslatedNotice`), а не
молчаливое умолчание.

**Структура маршрутов.** Английские страницы живут под `/en/` — `/en/`, `/en/{section}/`,
`/en/about/`. Формальный `i18n`-роутинг Astro не подключался: он рассчитан на полный параллелизм
контента по локалям, а у нас контент (`news`) одна коллекция без языкового поля. Вместо этого —
обычные страницы-дубликаты, использующие тот же слой данных, но англоязычный словарь строк.

**`src/lib/i18n.ts`** — центральный источник: `SECTION_LABELS_EN`, `SECTION_INTROS_EN` (реальный
перевод позиционирования каждого раздела, не urls сокращённая заглушка), `STATUS_LABELS_EN`, и
словарь `UI.ru`/`UI.en` для остальных строк интерфейса. Компоненты (`Header`, `Subscribe`,
`MarketsPanel`, `SearchIndex`, `Pagination`, `ThemeToggle`) получили необязательный проп `locale`
(`'ru' | 'en'`, по умолчанию `'ru'`) — ни один существующий вызов на русских страницах не пришлось
трогать.

**Переключатель языка и честные hreflang.** `altPath()` сопоставляет текущий путь с его аналогом
в другой локали. Для главной, хабов разделов и «О редакции» — точное соответствие
(`exact: true`), и туда же ставится `hreflang`. Для страниц без перевода (статьи, автор,
`/projects/`, Spotlight) — `exact: false`: переключатель всё равно ведёт куда-то полезное (на
англ./рус. главную), а не на 404, но `hreflang`-тег для такой пары **не** ставится — он утверждает
поисковику, что два URL это один и тот же контент на двух языках, а мы такого не гарантируем.

**`/projects/`** сознательно не продублирован на `/en/` — его реальное содержимое (названия
протоколов, категории DeFiLlama, цифры TVL) и так уже приходит по-английски от источника данных,
независимо от локали сайта; фабриковать `/en/projects/` ради нескольких строк интерфейса не
стали, обе версии шапки ведут на один и тот же `/projects/`.

**Заодно (найдено при аудите, что не хватает поиску):** `SearchIndex` теперь индексирует ещё и
`dek`, а не только заголовок — раньше читатель, помнящий факт из статьи, но не точную
формулировку заголовка, ничего не находил.

**Известный, осознанный пробел (закрыт в §23).** `VerificationMeter`'s `aria-label` по умолчанию
всегда на русском («N из 6 проверок пройдено») — компонент не получил проп `locale`, чтобы не
тянуть локализацию в самый глубокий слой ради одной фразы для скринридера. На английских
страницах это единственное место, где вспомогательная технология услышит русский текст среди
английского интерфейса — известный компромисс объёма этой итерации, не забытый баг.

## 23. Дочистка английской версии: реальный баг + перевод заголовков статей

Пользователь сообщил «кнопка EN появилась, но сайт не переводится» — расследование раскрыло два
независимых, не связанных друг с другом источника проблемы.

**Причина №1, инфраструктурная.** На Windows `pkill` не существует в git-bash — все прошлые
попытки «перезапустить» `astro preview` между итерациями на самом деле не убивали старый процесс,
а просто не могли занять порт 4321 (тот и оставался слушать). Пользователь физически видел билд
из предыдущей итерации. Фикс — `taskkill //F //PID <pid>` (PID через `netstat -ano | grep :4321`)
вместо `pkill`; это правило теперь в стандартном цикле итерации.

**Причина №2, реальный незамеченный баг.** `VerificationLog.astro` (аккордеон проверки под каждой
статьёй — статус-слово, счётчик «N из 6 проверок пройдено», список чек-пунктов) был пропущен при
первом переводе интерфейса: все строки были зашиты на русском без `locale`-пропа. Получил его,
плюс попутно те же по духу пропуски: чип «Все» и пустое состояние в `FilterBar.astro`, и
«Обновлено HH:MM UTC» в `Ticker.astro` (включая клиентский скрипт, перезаписывающий эту строку
раз в минуту, и форматирование самих чисел — `toLocaleString('ru-RU')` было зашито без учёта
локали, из-за чего английская версия показывала «76 762» с пробелом вместо «76,762» с запятой).

**Перевод заголовков и деков статей.** Пользователь явно расширил исходный скоуп («интерфейс на
EN, статьи пока RU») и попросил перевести хотя бы заголовки/деки, раз они — большая часть видимого
текста на скринах. Добавлены необязательные `title_en`/`dek_en` в схему `news` (и `note_en` для
`videos`, `role_en`/`bio_en` для `authors`) — заполнены для всех статей/видео/авторов, с
фолбэком на русский оригинал везде, где английского перевода ещё нет. Тело статьи остаётся
русским — это не отменяет решение §22, просто отодвигает границу «что уже переведено» на один
слой глубже.

**`/projects/` всё-таки продублирован на `/en/`** — решение §22 не сделать так пересмотрено:
хотя данные DeFiLlama и так на английском, вся *обвязка* (заголовки таблиц, тултип, лейблы
фильтров, переключатель Таблица/Карточки) была русской. Логика и разметка страницы вынесены в
общий `ProjectsPage.astro` (проп `locale`), `src/pages/projects/index.astro` и
`src/pages/en/projects/index.astro` — тонкие обёртки над ним. `fmtTvl`/`fmtDate` в
`defillama-client.ts` получили параметр локали (числа/месяцы форматируются `en-US` на английской
версии, а не всегда `ru-RU`).

## 24. Три новых раздела: Календарь, Трекер регулирования, Глоссарий

По запросу «чего не хватает как веб3-синьору» — три раздела, наполненные исключительно фактами
из уже опубликованных статей (никаких выдуманных дат/статусов):

- **`/calendar/`** (`events` коллекция) — даты и дедлайны с полем `precision` (`day` / `quarter` /
  `year`): если источник называет только квартал или год, страница так и показывает «Q4 2026» /
  «2027», а не выдумывает точность, которой нет в первоисточнике. Каждая запись ссылается на
  статью-первоисточник и на её же внешний источник.
- **`/regulation/`** (`regulations` коллекция) — статус активных биллей/правил (CLARITY, GENIUS,
  CFTC, SEC Regulation Crypto Assets, Nasdaq Texas, G20, IRS 1099-DA) с грубым `stage`
  (`active`/`stalled`/`early`/`final`) и опциональным «что дальше» — в отличие от календаря, это
  срез *текущего состояния*, а не хронология дат.
- **`/glossary/`** (`glossary` коллекция) — 10 терминов из собственных статей (TVL, range proof,
  федеративный сайдчейн, филибастер, cost basis, хешprice, LST, x402, перпы, захват управления),
  каждый с примером-ссылкой на реальную статью, а не абстрактным учебным определением.

Общий паттерн для всех трёх: shared-компонент (`CalendarPage.astro` / `RegulationTrackerPage.astro`
/ `GlossaryPage.astro`) с пропом `locale`, и пара тонких страниц `src/pages/{route}/index.astro` +
`src/pages/en/{route}/index.astro` поверх него — тот же приём, что и у `/projects/` из §23.

**Навигация переполнилась.** Добавление Calendar + Tracker в шапку (итого 12 пунктов у `.nav`)
вылезло за пределы типичных десктопных экранов; `overflow-x: auto` был и раньше, но без всякой
подсказки, что список вообще скроллится. Добавлена `mask-image`-заглушка (затухание правого края)
— решает только обнаружение, не тесноту саму по себе. Четвёртый новый раздел (Glossary) в шапку
уже не пошёл — вместо этого у Projects/Calendar/Tracker/Glossary появилась вторая ссылочная
строка в футере, чтобы не растить `.nav` до бесконечности.

## 25. Видео есть теперь во всех 9 разделах

До этого видео было только в Bitcoin/DeFi/Policy (4 ролика на 9 разделов). Добавлено по одному
реальному ролику в Ethereum, Stablecoins, RWA, AI, Fintech, Security — каждый подобран так, чтобы
тема совпадала с уже опубликованной у нас статьёй. Все 6 новых ID **проверены через
`youtube.com/oembed`** до того, как попасть в контент, а не взяты на веру из заголовков в выдаче
`WebSearch` (поиск иногда путает заголовок статьи CNBC и заголовок YouTube-загрузки того же
сюжета) — в этом заходе все кандидаты подтвердились с первого раза, но сама проверка теперь
обязательный шаг чек-листа (§27), а не разовая предосторожность.

## 26. Технический долг: кастомная 404, честный auto-discovery RSS

Финальный проход по «что забыто» перед тем, как звать это законченным:

- **`src/pages/404.astro`** — раньше не существовал вообще, читатель получал голый дефолт
  хостинга. Новая страница переиспользует `VerificationMeter` (0 из 6 — «проверять нечего, страницы
  не существует», обыгрывает сам смысл продукта) и существующий поисковый оверлей через тот же
  `data-search-trigger`, на который уже подписан `SearchIndex.astro` — ни одной новой строчки JS.
  Двуязычная (RU-блок, затем EN-блок), потому что статический хостинг отдаёт один 404 на весь
  сайт независимо от локали запрошенного URL; помечена `noindex` через новый проп `BaseLayout`.
- **`rss.xml`** был без сортировки, на русском без объявленной локали в самом контенте, и не
  показывал статус проверки. Добавлена сортировка по `publishedAt` (новые сверху), `<category>` с
  разделом и статус-проверка в описании каждого item; плюс `en/rss.xml` с `title_en`/`dek_en` (и
  RU-фолбэком). Оба фида объявлены через `<link rel="alternate" type="application/rss+xml">`.
- **Ложная тревога, которую стоит записать, чтобы не повторить.** Собственный аудит перед стартом
  этого блока ошибочно решил, что `/og-default.png` не существует — грep прошёл только по `public/`, но
  картинка на самом деле рендерится динамически через Satori в `src/pages/og-default.png.ts`.
  Урок: для файлов уровня `og-default.png`, у которых может быть либо статический файл, либо
  build-time роут, проверять надо реальным `curl` на живой билд, а не поиском по каталогу.

## 27. Формализованный чек-лист для будущих итераций

По запросу «промпт для синьора веб3» — зафиксирован цикл проверки, которым в реальности уже
пользовались весь этот блок работы, чтобы не терять его между итерациями:

1. `npx astro check --minimumSeverity error` → 0 ошибок.
2. `npx astro build` → свежий `dist/`, без warnings.
3. Убить старый `astro preview` через `taskkill` (не `pkill` — см. §23), поднять новый.
4. Для каждой `/en/...` страницы — `grep -oP '[а-яА-ЯёЁ]{3,}'` на живом HTML должен вернуть 0
   совпадений (кроме текста самих статей, который остаётся русским по правилу §22/§23).
5. Playwright-скриншот в обычной теме **и** с `document.documentElement.dataset.theme = 'dark'`,
   плюс отдельный проход на viewport 375px — смотреть на картинку, не только проверять код 200.
6. Любой внешний URL-источник (статья, календарь, трекер, глоссарий, видео) — проверять, что он
   реально резолвится, для YouTube конкретно через `youtube.com/oembed` (см. §25).
