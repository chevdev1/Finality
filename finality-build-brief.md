# Finality — бриф на сборку пилотного сайта

> Этот файл — единственный источник правды по проекту. Презентация `finality-concept.pptx` идёт приложением: в ней макеты и картинки. Если текст файла и презентация расходятся, прав файл.
>
> Файл написан так, чтобы его можно было целиком отдать ИИ-агенту (Claude Code, Cursor) как промт, и так, чтобы его прочитал живой разработчик. Разделы «Задача», «Что уже решено» и «Definition of done» — обязательные к прочтению, остальное справочник.

---

## 1. Задача

Собрать пилотное новостное издание **Finality** — англоязычный сайт о крипте и финтехе для глобального рынка. Это первый из пяти сайтов сети; остальные четыре будут отличаться структурно, а не только цветом, поэтому код с самого начала пишем как переиспользуемую основу, а не как один сайт.

Аудитория: розничные крипто-инвесторы и финтех-профессионалы, читают с телефона в перерывах, хотят за несколько секунд понять, что случилось и почему это важно.

Две задачи интерфейса:
- **Главная**: за 5 секунд показать главное событие дня и увести в ленту.
- **Статья**: дочитывание и переход по внутренним ссылкам.

Разделы: Bitcoin, Ethereum и L2, DeFi, стейблкоины и платежи, регулирование, RWA и токенизация, AI × crypto, финтех, безопасность и взломы, плюс спонсорский раздел Project Spotlight.

## 2. Что уже решено, менять без обсуждения нельзя

Эти решения приняты на этапе концепции и утверждены. Они не предмет творчества исполнителя.

### 2.1 Идея и сигнатурный элемент

Издание называется **Finality** — в блокчейне так называют момент, когда транзакцию уже нельзя откатить.

Сигнатура сайта — **счётчик из шести клеток** рядом с каждым материалом. Каждая клетка = одна пройденная проверка из фиксированного списка:

| № | Проверка |
|---|---|
| 1 | Первоисточник найден и проставлен ссылкой |
| 2 | Ончейн-данные подтверждают утверждение |
| 3 | Независимое второе издание сообщает то же самое |
| 4 | Официальное заявление стороны получено |
| 5 | Цифры сверены редакцией |
| 6 | Подпись выпускающего редактора |

Правила, от которых зависит смысл всей затеи:

- Шесть закрашенных клеток подряд = логотип издания. Логотип и максимальное состояние счётчика — один и тот же объект.
- Счётчик показывается везде, где есть заголовок: лента, главная история, OG-картинка, рассылка, блок «связанные материалы».
- В статье счётчик разворачивается в журнал проверок: у каждой пройденной проверки своё время, у непройденной — статус OPEN.
- **Спонсорский материал не получает счётчик никогда.** Отсутствие счётчика само по себе маркировка.
- Клетки — не декор. Если конкретная проверка не пройдена, клетка пустая, даже когда очень хочется.

### 2.2 Цвет

```css
--ledger:   #F2F4F0;  /* фон страницы: холодная, чуть зеленоватая бумага */
--paper:    #FBFCFA;  /* панели, врезки */
--ink:      #0F1613;  /* текст, закрашенные клетки, тикер */
--graphite: #56615B;  /* второстепенный текст, метаданные */
--rule:     #D3D9D4;  /* линейки и границы */
--pending:  #FFD23F;  /* единственный громкий цвет */
--up:       #0B7A4E;  /* только рост цены */
--down:     #C8322B;  /* только падение цены */
--guest:    #3D5AFE;  /* цвет спонсора, подменяется на каждый Spotlight */
```

Ограничения:

- `--pending` разрешён ровно в четырёх местах: главная история дня, статус «Developing», блок «Риски» в Spotlight, кнопка подписки. Больше нигде.
- `--up` и `--down` — только цены и графики цен. Никогда как акцент интерфейса.
- `--guest` живёт только внутри страницы Spotlight и только в четырёх элементах: плитка логотипа проекта, символ токена, график токеномики, кнопка CTA.
- Контраст: все пары проходят WCAG AA. Проверено: Ink на Ledger 16.6:1, Graphite на Ledger 5.8:1, Up 4.9:1, Down 4.8:1, белый на Guest 5.1:1. При любой правке палитры пересчитать.

Чего в этом проекте не бывает: тёмного фона с неоновым акцентом, фиолетовых градиентов, стеклянных карточек, светящихся сфер. Клиент отверг несколько концепций именно за это.

### 2.3 Шрифты

Все три бесплатные, ставим self-hosted через Fontsource, никаких запросов к Google Fonts.

| Роль | Шрифт | Где применяется |
|---|---|---|
| Display | **Redaction** 700 | Все редакционные заголовки, названия разделов |
| Status | **Redaction 70** 700 | Единственное слово «DEVELOPING». Больше нигде |
| Body | **Atkinson Hyperlegible Next** 400/700 | Весь основной текст, интерфейс |
| Data | **Martian Mono** 400/600 | Цены, время, хэши, метки, счётчики |

Почему Atkinson: он разработан для слабовидящих, у него различимы 0/O и 1/l/I. В новостях, где смысл несут суммы и адреса, это функциональное требование, а не вкус.

**Заголовки Spotlight набираются гротеском (Atkinson), а не Redaction.** Redaction = редакция. Это второй уровень защиты от путаницы со спонсорским контентом.

Типографическая шкала (десктоп): 84 / 60 / 40 / 28 / 21 / 18 / 11. Мобильная: 40 / 28 / 21 / 18.5 / 16.5 / 11.

### 2.4 Композиция

- Сетка 12 колонок, поля 24 px, максимальная ширина 1440 px.
- Главная: лента `1fr` + правый рельс `380px`. Главная история: `1fr` + журнал проверок `360px`.
- **Лента — это строки реестра, а не сетка карточек**: время, счётчик, заголовок, раздел. Без теней, без скруглений, без превью-картинок в ленте.
- Скругления в проекте отсутствуют как класс. Радиус 0 везде, кроме аватаров авторов.
- Единственная пунктирная рамка на сайте — вокруг спонсорского блока.

## 3. Стек и ограничения

- **Astro** со static output, острова только там, где нужна интерактивность (тикер, ⌘K, журнал проверок, мобильное меню). Альтернатива — Next.js с ISR, если клиент настаивает; тогда ревалидация главной 60 секунд.
- Контент — markdown/MDX в репозитории на старте, с готовностью переехать в headless CMS. Структура фронтматтера описана в разделе 6.
- Никаких UI-китов и готовых тем. CSS пишем руками, токены из раздела 2.2 в `:root`.
- JS в ленте минимальный. Страница должна быть полностью читаема и без него.
- Изображения: AVIF/WebP, `srcset`, обязательные `width`/`height`.

## 4. Шаблоны страниц

### 4.1 Главная

Сверху вниз: тикерная лента → шапка с логотипом, навигацией по разделам и поиском → главная история дня → лента последних материалов с правым рельсом → подписка.

Главная история занимает первый экран, фон `--pending`. Внутри: раздел, статус, время обновления, H1, лид, автор с фото. Справа (на десктопе) или снизу (на мобильном) — журнал проверок.

Правый рельс: рыночная панель (с явной пометкой источника данных), блок Project Spotlight в пунктирной рамке, хабы разделов со счётчиком материалов за день, форма подписки.

Мобильная главная: тикер → шапка → свайп-табы разделов → главная история с заголовком 40 px → лента строками. Главный заголовок должен помещаться на первый экран телефона 360 px целиком вместе с лидом и счётчиком.

### 4.2 Новость или статья

Хлебные крошки → раздел и статус → H1 → лид → автор с фото и био → даты публикации и обновления в `<time datetime>` → блок «Key takeaways» из трёх пунктов до текста → оглавление для лонгридов (липкое на десктопе, выпадающее на мобильном) → текст с врезками данных каждые 3–4 абзаца → три связанных материала со счётчиками → карточка автора.

Длина строки 64 знака, кегль 18 px, интерлиньяж 1.6.

Жёлтая плашка у заголовка ведёт в журнал проверок. Журнал раскрывается на месте, страница при этом не прыгает.

### 4.3 Project Spotlight

Спонсорская статья о проекте. Проект получает свой акцентный цвет, но остаётся гостем в чужой дизайн-системе.

Порядок блоков:

1. Чёрная плашка «Partner content · Paid for by [Project]» — над всем, включая hero. Видна до скролла.
2. Hero: плитка логотипа проекта в цвете `--guest`, заголовок гротеском, лид.
3. Панель ключевых фактов: сеть, токен, дата запуска, аудиты, инвесторы, TVL или объём.
4. «Что это» простыми словами.
5. «Как это работает» со схемой.
6. Токеномика с графиком распределения.
7. Роадмап таймлайном. **Здесь нумерация уместна**, потому что это настоящая последовательность. В остальных местах сайта декоративных номеров 01/02/03 нет.
8. Команда и бэкеры.
9. **«Риски и открытые вопросы»** — обязательный блок, фон `--pending`, заголовок в Redaction, подпись «Added by Finality editors». Пишет редакция, не клиент. Это то, что делает раздел продаваемым и не убивает E-E-A-T.
10. FAQ.
11. CTA на официальный сайт: `rel="sponsored noopener"`, подпись объясняет, что откроется.

Счётчика проверок на этой странице нет. Рамка вокруг контента пунктирная.

### 4.4 Хаб раздела или тега

Вводный текст 150–300 слов (он и есть SEO-смысл страницы) → закреплённые материалы → лента → пагинация `?page=2` с self-canonical.

### 4.5 Страница автора

Фото, экспертиза, соцсети через `sameAs`, список всех материалов. Нужна не для читателя, а для доверия и разметки Person.

## 5. Моушен

Спека целиком. У каждой анимации указано назначение. **Если у анимации нет назначения — её нет.**

| Элемент | Триггер | Длительность | Easing | Назначение |
|---|---|---|---|---|
| Тикерная лента | Всегда | ~40 px/с | `linear` | Показывает, что рынок живой. Пауза при hover и при `document.hidden` |
| Вспышка цены | Новый тик | 160 мс вкл / 180 мс выкл | `ease` | Какая цена изменилась. Только `background-color` через transition, не keyframes |
| Заполнение клеток в hero | Первая загрузка за сессию | 220 мс, stagger 60 мс | `cubic-bezier(.23,1,.32,1)` | Единственная оркестрованная сцена. Объясняет, что клетки копятся |
| Новая проверка в живой истории | Push с сервера | 200 мс | `cubic-bezier(.23,1,.32,1)` | Индикация состояния: одна клетка заполнилась |
| Поиск и ⌘K | Клавиатура, клик | 0 мс | — | Открывается десятки раз в день. Анимация только мешает |
| Hover строки ленты | `hover: hover` и `pointer: fine` | 150 мс | `ease` | Обратная связь на наведение |
| Нажатие кнопки | `:active` | 120 мс | `cubic-bezier(.23,1,.32,1)` | `scale(0.97)`: интерфейс услышал |
| Мобильное меню | Тап | 240 вход / 180 выход | `cubic-bezier(.32,.72,0,1)` | Пространственная связь: выезжает от края, туда же уходит |
| Журнал проверок | Клик | 200 вход / 150 выход | `cubic-bezier(.23,1,.32,1)` | `grid-template-rows: 0fr → 1fr`, без скачка текста |
| Тост «Subscribed» | Отправка формы | 200 вход / 150 выход | `cubic-bezier(.23,1,.32,1)` | Подтверждает действие. Слово совпадает с кнопкой Subscribe |

Правила:

- Выход всегда быстрее входа.
- Никакого `transition: all` и никакого `ease-in` на UI.
- Все hover-эффекты внутри `@media (hover: hover) and (pointer: fine)`.
- `prefers-reduced-motion: reduce` — лента становится статичным списком, stagger и сдвиги убираются, клетки проявляются только прозрачностью, вспышки цвета остаются.
- Не анимируем: переходы страниц, подъём карточек при наведении, scroll-reveal, параллакс.

## 6. SEO

### 6.1 URL и разметка

| Шаблон | URL | JSON-LD |
|---|---|---|
| Главная | `/` | `Organization` с логотипом, `WebSite` + `SearchAction` |
| Новость | `/news/{slug}` | `NewsArticle`, `BreadcrumbList`, `Person` |
| Разбор в разделе | `/defi/{slug}`, `/policy/{slug}` … | `NewsArticle` или `Article` для эксплейнеров |
| Spotlight | `/spotlight/{slug}` | `Article`, `FAQPage`, `BreadcrumbList` |
| Хаб раздела и тега | `/defi/`, `/tag/{tag}/` | `CollectionPage`, `ItemList`, `BreadcrumbList` |
| Автор | `/author/{name}` | `ProfilePage` + `Person` с `sameAs` |

### 6.2 Обязательная гигиена

- Семантический HTML5: `article`, `header`, `nav`, `time datetime`. Один H1 на страницу, иерархия заголовков без пропусков.
- `datePublished` и `dateModified` на каждом материале. При существенной правке — видимая пометка об исправлении.
- Open Graph и Twitter-карточки. Шаблон OG-изображения: жёлтый фон, счётчик, заголовок Redaction, логотип (макет в презентации).
- `sitemap.xml`, отдельный news-sitemap (материалы за последние 48 часов), RSS по разделам. `hreflang` закладываем в архитектуру, включаем только когда появятся языковые версии.
- Спонсорский контент: видимая плашка + `rel="sponsored"` на всех исходящих ссылках. Это требование спам-политик Google, а не наша перестраховка.

### 6.3 Core Web Vitals

Цели: LCP < 2.5 с, CLS < 0.1, INP < 200 мс.

- LCP — это текст заголовка, а не картинка. В hero картинки нет by design.
- Preload одного файла: Redaction 700, latin subset. `font-display: swap`, для запасного шрифта прописать `size-adjust`, чтобы подмена не двигала текст.
- Тикер фиксированной высоты, резерв места под рекламу и изображения — иначе CLS.
- Замер на реальном мобильном соединении, не на десктопном Lighthouse.

### 6.4 Перелинковка

Схема: хаб раздела → статья → связанные материалы → автор.

- Каждая статья: ссылка на хаб раздела через крошки, 2–4 ссылки в тексте на объясняющие материалы, 3 связанных внизу, ссылка на автора.
- Связанные подбираются по разделу или по сущности (протокол, актив), не случайно.
- В Spotlight ведут только хаб `/spotlight/` и помеченный блок на главной. Редакционные «связанные материалы» на спонсорские страницы не ссылаются.

## 7. Контент

Никакого lorem ipsum ни на одном этапе, включая черновую вёрстку. Для запуска нужно 10–12 реальных новостей за последние 7 дней по разным разделам: потоки в ETF, регулирование, стейблкоины, RWA, DeFi, взломы, финтех-платежи, AI × crypto.

Заголовки и лиды пишутся своими словами, тексты источников не копируются. Ссылка на первоисточник — обязательное поле, а не опция: без неё не закрывается проверка №1.

Цены и графики в демо-режиме помечаются как демо-данные прямо в интерфейсе. Когда подключится реальный источник котировок, пометка убирается вместе с моком.

Минимальный фронтматтер материала:

```yaml
title: ""
dek: ""            # лид
slug: ""
section: ""        # bitcoin | ethereum | defi | stablecoins | policy | rwa | ai | fintech | security
status: ""         # developing | final
publishedAt: ""    # ISO 8601
updatedAt: ""
author: ""         # slug автора
checks:            # журнал проверок, только пройденные
  - id: 1
    at: ""
sources:
  - url: ""
    title: ""
related: []        # slug'и, 3 штуки
sponsored: false   # true только для Spotlight
```

Тексты интерфейса: активный залог, кнопка говорит, что произойдёт. «Get the 7:00 brief», «Subscribe», «Go to project.xyz». Название действия не меняется по ходу флоу: кнопка Subscribe даёт тост Subscribed.

## 8. Definition of done

Сайт считается сданным, когда выполнено всё:

**Функциональность**
- [ ] Все пять шаблонов собраны: главная, статья, Spotlight, хаб раздела, страница автора.
- [ ] На сайте 10–12 реальных материалов, у каждого проставлены источники и журнал проверок.
- [ ] Тикер работает, встаёт на паузу при hover и в скрытой вкладке.
- [ ] ⌘K открывает поиск мгновенно, без анимации.

**Качество исполнения**
- [ ] Адаптив до 360 px без горизонтального скролла.
- [ ] Видимый фокус клавиатуры на всех интерактивных элементах, порядок табуляции логичный.
- [ ] `prefers-reduced-motion` реализован по разделу 5.
- [ ] Контраст не ниже WCAG AA на всех парах.
- [ ] Сайт читаем с выключенным JS.

**SEO**
- [ ] JSON-LD по разделу 6.1 валидируется в Rich Results Test без ошибок.
- [ ] Один H1 на страницу, иерархия без пропусков.
- [ ] sitemap, news-sitemap, RSS отдаются и валидны.
- [ ] LCP < 2.5 с, CLS < 0.1, INP < 200 мс на мобильном.

**Проверка по фирменному стилю** (прогнать перед сдачей)
- [ ] Если закрыть логотип, издание узнаётся? Если нет — сигнатура реализована слабо.
- [ ] Нет ли на сайте одинаковых карточек с одним радиусом и одной тенью?
- [ ] Каждый структурный элемент (нумерация, лейблы, разделители) несёт информацию, а не украшает?
- [ ] Главная история читается за 5 секунд на экране 360 px?
- [ ] Спонсорский материал нельзя спутать с редакционным: плашка, нет счётчика, пунктир, другой шрифт заголовка?

## 9. Что нужно получить от клиента до старта

1. Подтверждение названия **Finality** и домена.
2. Логотип и цвет первого спонсора для Spotlight, плюс данные проекта: название, сайт, описание на 2–5 предложений, сеть, токен, аудиты, инвесторы.
3. Источник рыночных данных: свой API-ключ или наш выбор провайдера (влияет на бюджет).
4. Фото, био и соцсети авторов — без них не закрывается разметка `Person` и половина смысла E-E-A-T.
5. Решение по CMS: остаёмся на markdown в репозитории или сразу подключаем headless.

## 10. Чего в этом проекте не делаем

Список составлен по итогам концепции. Каждый пункт — то, к чему тянет по привычке и что разрушит замысел.

- Тёмная тема с неоновым акцентом, фиолетовые градиенты, стеклянные карточки.
- Сетка одинаковых карточек с превью-картинками вместо ленты-реестра.
- Декоративная нумерация секций 01 / 02 / 03. Номера только в роадмапе и списке проверок.
- Scroll-reveal, параллакс, подъём карточек при наведении.
- Акцентные полоски по краю блоков и подчёркивания под заголовками.
- Цвет спонсора за пределами страницы Spotlight.
- Счётчик проверок как украшение, где реальных проверок не было.
